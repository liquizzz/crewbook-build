Release: **$ARGUMENTS** (no version given: the milestone that is done). You are the Lead.

1. Read `.claude/project.json` (level). Check gate G4 for the milestone with the criteria in `.claude/commands/gate.md`: every issue closed through `/build done`, tests for each level green, CI green on `dev`. If it is not ready, report what is missing and stop.
2. **Staging:** merge `dev` into `staging` (CI on GitHub builds the `:staging` image; with CI on this machine `node scripts/run.mjs staging` builds it here). Ask for the regression on `staging` (Full: the Test session; Lite: Dev1; prompt: `Run the regression for v<X.Y.Z> on staging.`), with the update and rollback scripts on the staging database when the milestone changes data (rule "Data changes" in `CLAUDE.md`). Then open the PO for the acceptance (rule "Opening sessions"; prompt: `Accept v<X.Y.Z> on staging.`): it tries every acceptance criterion of the milestone on `staging`, records the results in `docs/product/handover/<version>.md` and opens a defect for each failure. A defect is fixed on `dev` and merged into `staging` again; then only the affected area and the main journeys are tested again.
3. **The owner's try:** `node scripts/run.mjs staging` starts the image of `staging` (pulled from GitHub, or built here with CI on this machine) (it waits for the healthcheck and opens the browser); `node scripts/run.mjs --source` only if that image is missing. Give the owner the link to open it (or the one command that starts it) and the PO's 3-5 acceptance scenarios in plain words (steps, expected result, one example of a wrong result), and for a product with screens always one at a narrow window (about 390 px wide). Commands are for the owner's shell. Wait for "All pass" or the failures; turn each failure into a defect and fix it as in step 2.
4. **`/release demo` stops here:** report the image tag and the link or command to show the client. Nothing is tagged. A later `/release` of the same milestone skips steps 2 and 3 when nothing reached `staging` since.
5. **`/release`:** ask the PO to finish the handover (`docs/product/handover/<version>.md`: delivered, changes, what the client must prepare, accepted risks, how to roll back, sign-off). Copy the tasks' actual AI times into the milestone file and `docs/ai-log.md`. Run `node scripts/release.mjs --write` (it handles both line endings and warns if the changelog was not updated), write `docs/releases/<version>.md`, update `CHANGELOG.md`, the SRS revision row and the Stage line in `CLAUDE.md`. Check gate G6 and ask for the final approval in the fixed form (gate table, `For you` block, question): what will be published, the regression and the PO's acceptance on `staging`, the scenarios the owner passed, the evidence (CI, tests, image), open risks, and the handover to send the client.
6. **After "Approved", no new tests:** merge into `main` exactly the `staging` commit that was accepted (nothing else reached `staging` since), tag, `git push origin main <version>`, `gh release create`. Check live state (`gh run list --limit 3`): the tag builds `ghcr.io/<owner>/<repo>-app:<version>` with its SBOM and, on a public repo, a build attestation; `node scripts/run.mjs <version>` starts it and it answers its healthcheck. Report in a few lines the image and that command. If the release fails in production, roll back to the previous tag (`node scripts/run.mjs <previous version>`, plus the rollback script when data changed) with the owner's OK.
